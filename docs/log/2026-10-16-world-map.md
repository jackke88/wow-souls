# Reusable parchment area map

The user asked to add the map, move it toward the Elden Ring feeling cheaply and reuse existing material. The result keeps WoW's actual hand-drawn geography and layers one shared palette and restrained native UI over it. No commits made; animation/extractor work remains untouched.

## What was built

- M (rebindable in Controls) or **Menu → Map** opens the Elwynn area chart. Existing gamepad bindings are preserved; the Map menu entry is reachable by pad. The map is a system-menu page and shares its pause preference, cursor release and gameplay-input gate. Closing consumes the frame's action input. Entering through the menu does not immediately place a pin.
- Mouse wheel / +/- / L2/R2 zoom; drag / arrows / left stick pan; click or Enter/A places one marker. Delete/X removes it; R/Y finds the player; Escape/B closes. Toolbar buttons provide mouse access to zoom, recenter, clear and close.
- The player uses actual avatar coordinates and WorldMapArea projection. A contrasting location ring, a gold marker, a small compass and a crosshair stay legible at every zoom. Pan is bounded; zoom stays between 1× and 5×. The overview preserves the chart's aspect ratio, using spare width on ultrawide rather than stretching geography.
- One marker is saved per character in `map-v1.txt`. Unattended checks use isolated files. Invalid/future-format files are preserved: the marker remains usable in the session and the UI explains why it cannot be saved.
- Quest NPCs use compact grouped seals (details below). No enemy markers, fast travel or new discovery progression. The whole current area is visible from the start. Elwynn is the prototype's default area (AreaTable 12); the loader accepts other area ids without requiring new region-specific artwork.

## Reuse and cost

`cartography/art.rs` reads WorldMapArea / WorldMapOverlay / AreaTable metadata and the player's installed `Interface/WorldMap` BLPs through the existing MPQ chain, read-only. It composes the twelve base tiles plus overlays, respecting partial edge tiles and alpha, then applies one luminance/olive/sepia treatment with subtle grain. This produces one 1002×668 RGBA texture in memory (about 2.55 MiB raw pixel data). It is composed once per run, reused on every opening and zoomed by the UI.

The map required **zero new image-generation calls, zero map-specific dependencies and no new map-art files**. All styling, positioning and interaction are code; the installed geography and lettering are reused. Future areas can use the same loader and treatment. There is no API cost when the player opens or uses the map. No installed map art is exported into shipped assets; captures below are local gitignored evidence.

Visual reference: [Bandai Namco's Elden Ring gameplay/map overview](https://www.bandainamcoent.com/news/elden-ring-introduction-part-3-gameplay-overview). The sparse marker treatment and restrained chart presentation are inspiration; the geography remains WoW's.

## Quest signs on the map

The user clarified that the requested changes to **!** and **?** apply only to the map. The original overhead WoW M2 signs, their yellow/grey colors and their spin/bob are preserved in `quests/ui.rs`.

`cartography/view/pins.rs` reuses the existing worn octagonal seal and Georgia font for map signs. New offers use warm gold **!**, ready hand-ins a pale gold **?**, and low-level/incomplete states muted grey. Data and priority come from the existing quest rules, with positions from the world manifest. No new assets, image generation or dependencies.

Nearby NPCs share a compact group with a count. Both glyphs remain visible when that group contains offers and hand-ins, and locations separate as zoom increases. Moving the mouse over a group, or panning it under the map crosshair with a gamepad/keyboard, shows NPC names and their actual quest status. Player and personal marker remain above the quest layer.
