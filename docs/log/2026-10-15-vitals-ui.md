# Elden Ring reference UI

The user requested a Souls / WoW UI overhaul, initially starting with health, mana/rage, stamina and XP. They first approved a generated class-emblem concept, then rejected the result as looking AI-generated, linked Interface In Game and asked for the remaining UI to be as close to Elden Ring as possible. They then corrected the code-only pass as too flat: the reference has subtle material depth, etched icons, distressed fine gold edges and smoky textured panels. The final direction combines native game UI with small reusable material assets.

## Implementation

- `hud/vitals.rs`: narrow, unequal HP, mana/rage and stamina meters; a small octagonal level seal; separate subdued XP line at the bottom. Class selects blue mana or amber rage. Meter length depends on the maximum stat with bounded footprint. Existing HP/stamina damage chips and XP glide/level-up reset remain. All text and values are live code, with max-level handling. Status and souls hide while inventory/equipment or the quest log is open.
- `hud/theme.rs` and `hud/theme/skin.rs`: shared smoke/olive surfaces, ivory serif text, muted gold focus and material pieces. Two embedded RGBA atlases contain only etched category icons, normal/selected empty slots, empty meter trim, neutral fill pigment, an empty seal and a feathered panel texture. Native shapes remain a fallback if an atlas cannot decode. Material bindings update when their state changes.
- Inventory now uses a five-column grid with twenty cells per page and matching horizontal/vertical keyboard/pad movement. Equipment uses a four-column grid, with all twenty slots reachable by keyboard/pad. Existing item descriptions, comparisons, use/equip/take-off, save behavior and mouse interaction are retained. A navigation test checks the equipment grid and reachability.
- Inventory, equipment, dialogue, quest log/reward cards, shops/bank/training, title, creation and system/settings menus share the material theme. The system menu is docked left and has six etched category icons; detailed settings retain their wider panel. Ability slots share the textured normal/selected frame and hide under modal item/quest screens.
- Souls, enemy/boss bars, lock-on and YOU DIED use native text/shapes and material trim. The default UI does not load DSR HUD art/font. `WOWSOULS_UI=legacy` enables the earlier DSR/parchment appearance; `WOWSOULS_VITALS=legacy` compares only the old status; `WOWSOULS_HUD=0` keeps the plain developer HUD. F3 still toggles the developer text, which starts hidden in the new theme.
- Unrelated animation, combat and extractor edits were preserved. The user is running Claude on animations concurrently. Local UI captures use a copied executable, so they do not lock the shared build output.

## Reference and asset provenance

Examined the [HUD](https://interfaceingame.com/screenshots/elden-ring-boss-fight/), [equipment](https://interfaceingame.com/screenshots/elden-ring-equipment/) and [in-game menu](https://interfaceingame.com/screenshots/elden-ring-menu-in-game/) at full resolution. The user's attached menu reference is retained locally as `docs/evidence/ui-vitals/er-menu-reference.png`.

The built-in image tool generated `crates/wow-souls/assets/ui/etched-icons-v1.png` and `weathered-trim-v1.png` with that screenshot as the sole style input, using transparent background mode. The original output pixels and alpha are preserved. No installed game files were generation inputs. Existing WoW item/race/class icons remain loaded from the user's install, as before. All resource fills, labels and numbers remain independent of the artwork. Complete exact prompts are in `crates/wow-souls/assets/ui/prompts.md`.

The rejected bronze class-emblem atlas was removed from game assets. The earlier concept and comparison captures remain local evidence; the rejected atlas is in `cache/ui-vitals/rejected-atlas-v1.png`. The intermediate flat pass is recorded with `er-*` filenames. Final material-pass evidence uses `material-*` filenames.

## Verification

The material UI builds successfully. Live inspection covered the equipment/inventory grids, system and graphics menus, prompt cards and character selection/creation. HUD captures cover 1280×720, 1600×900, 1920×1080 and 2560×1080, plus an empty DSR cache, Mage casting and a Warrior kill crossing XP 390 → 442 / level 1 → 2. Every completed capture reports `WOWSOULS_CHECK ok`. The final roster/contrast fixes and exact workspace gate results are recorded in `2026-10-16-character-roster.md`.

The 2026-10-16 inspection caught a material color synchronization bug: the resource value/gradient followed Mana, but the embedded pigment tint could retain startup Rage. `vitals::update` now updates both together. Menu fixtures were also corrected to issue Talk after NPC initialization, use a level-1 character for starter quests and clear screenshot environment variables between menu stills and video captures.

`cache/ui-vitals/capture.ps1` creates isolated Mage/Warrior characters and quest saves for multiple resolutions, no-DSR-cache, casting and combat/XP checks. `cache/ui-vitals/screens.ps1` captures representative screens with isolated saves and temporary NPC fixtures. These do not modify real character slots or either game installation. Logs and videos are under `cache/ui-vitals/`; screenshots are under `docs/evidence/ui-vitals/`.

No commits requested or made.
