# The Dark Souls HUD (sub-project F) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline, the user asked for no
> questions). Steps use checkbox syntax. **Deviation from the template, on purpose:** this plan gives exact
> interfaces, formats, test names with their assertions, commands and expected output, but not the whole source
> of every file: the source is written once, straight into the repo, by the same hands that execute the plan
> (as in plans D2b and D3). Nothing is committed (the user commits).

**Goal:** the game's HUD is Dark Souls Remastered's own art and layout, read from the install by a new
`wow-souls-dsr hud` command and drawn from `cache/dsr/hud/` (spec
`docs/superpowers/specs/2026-10-08-ds-hud-design.md`).

**Architecture:** three new readers in `dsr-formats` (TPF, DRB, CCM), a `hud` command in `dsr-cache` that crops
the HUD's sprites and font pages into PNGs plus one text manifest, and a `hud/` module in the game that draws
them as Bevy UI nodes in a 1280 x 720 layout space (`UiScale`). No cache: the old plain HUD.

**Tech stack:** Rust 1.98, Bevy 0.18.1 UI (`ImageNode`), `texpresso` 2 (DXT decode) and `png` 0.18 (both
already in `Cargo.lock`, so every cargo call here uses `--offline`), `flate2`.

Conventions that hold for every task: `cargo ... -j 4`; fmt + `clippy -D warnings` per task; install tests need
`DSR_DIR="C:/Spel/Dark Souls Remastered" WOW_DATA="C:/Spel/World of Warcraft 1.12/Data"` in the same shell
command; DS-derived bytes never in tests (build bytes in the test); never write inside either install.

Format (PC): `"TPF\0"`, `i32` data size, `i32` count, `u8` platform (0), `u8` flag2, `u8` encoding (0 ASCII-ish,
1 UTF-16LE, 2 Shift-JIS), `u8` 0; then `count` 0x14-byte entries `{u32 offset, i32 size, u8 format, u8 type,
u8 mips, u8 flags1, i32 name offset, i32 has-float-struct}`. Texture bytes are a DDS file, wrapped in a DCX when
`flags1` is 2 or 3. Platform other than 0: error.

### Task 2: DRB reader

**Files:** create `crates/dsr-formats/src/drb.rs`; modify `lib.rs`.

Facts (spec "What the install says"): header `"DRB\0"` + 3 x `i32` 0; section `STR\0` (`i32` length, `i32`
count, `i32` 0, then UTF-16 NUL strings, offsets are byte offsets into that blob); then sections `TEXI`
(count x 16: name offset, path offset, 2 x i32), `SHPR`, `CTPR`, `ANIP`, `INTP`, `SCDP` (each one blob),
`SHAP` (count x 8: type string offset, `SHPR` offset), `CTRL` (count x 8), `ANIK`, `ANIO`, `ANIM` (a
count x 48 table, then more bytes: **skipped by searching the next tag `SCDL`**), `SCDL`, `DLGO` (count x 32:
name, `SHAP` byte offset, `CTRL` byte offset, 5 x i32), `DLG\0` (count x 64: name, `SHAP` byte offset, `CTRL`
byte offset, 5 x i32 0, `i32` object count at +32, `i32` first `DLGO` byte offset at +36, `i32` position at +40
(`x | y << 16`), `i32` size at +44 (`w | h << 16`)), `END\0`. A section header is `tag, i32 length, i32 count,
i32 0`; the body is `length` bytes, except `ANIM`. `SHAP` entry `i` belongs to the `i`-th item in file order:
dialog 0, its objects, dialog 1, its objects ... so a dialog's own shape is `dlg.shap_offset / 8` and object `k`'s
is `dlgo.shap_offset / 8`.

API: `read(&[u8]) -> Result<Drb>`; `Drb { textures: Vec<String>, dialogs: Vec<Dialog> }`;
`Dialog { name, rect: Rect, objects: Vec<Object> }`; `Object { name, shape: Shape }`;
`Rect { left, top, right, bottom: i16 }` with `width()` / `height()`;
`Shape::{Null, Dialog, Sprite { uv: Rect, texture: i16, blend: u8, tint: u32 }, MonoRect { color: u32 },
GouraudRect { colors: [u32; 4] }, Text { color: u32, size: i32 }, Other(String)}` (every variant but `Other` carries
its `rect` through `Object.rect`); `Drb::dialog(&self, name) -> Option<&Dialog>`; colours are `0xAARRGGBB` from the
bytes `A R G B`. `Sprite`: uv `i16 x 4` at +16, texture `i16` at +24, blend `u8` at +27, tint 4 bytes at +32
(`A R G B`). `MonoRect`: last 4 bytes. `GouraudRect`: the four `A R G B` values at +20, +24, +28, +32 in the order
top-left, top-right, bottom-left, bottom-right (**check against the install**: `BG_grad00` is transparent at
the top and alpha 200 at the bottom). `Text`: colour at +16, size at +24.

- [ ] Tests first with a builder `drb_of(&[DlgSpec])` that writes all sections: `a_dialog_with_a_sprite_decodes`
  (rect, uv, texture, blend, tint), `mono_rect_color_reads_argb_in_byte_order`, `a_sub_dialog_object_is_a_dialog_shape`,
  `objects_are_found_by_their_dialog` (two dialogs, offsets), `unknown_shape_types_are_other`, `bad_tag_is_an_error`,
  `an_anim_section_longer_than_its_table_is_skipped`.
- [ ] Install test `the_menu_drb_reads` (skips): 638 dialogs, 53 textures, `F20-00` has 92 objects, `bar_1_hp` is a
  `Sprite` with texture `Menu08` and uv `(6, 488, 138, 512)`, rect `(175, 76, 907, 89)`; `plate_hp` is a `MonoRect` with
  `0xFF0A0A0A`; `F23_YouDied/BG_bar` colour `0xC8000000`; `enemy_HP/text_param_name` is `Text`.
- [ ] fmt + clippy; PROVENANCE line (SoulsFormatsNEXT `DRB.cs`, layout checked against the install).

### Task 3: CCM reader

**Files:** create `crates/dsr-formats/src/ccm.rs`; modify `lib.rs`.

Format: `i32` version (`0x10001`), `i32` file size, `i16` font size (58), `i16` texture width, `i16` height, `i16`
(32), `u16` group count at 0x10, `u16` glyph count at 0x12, `i32` groups offset (0x20) at 0x14, `i32` glyphs offset at
0x18; groups are `i32 first, last, glyph index` (12 bytes); glyphs are 24 bytes: `f32 u0 v0 u1 v1` (atlas pixels as
exact floats, divide nothing), `i16 pre, width, advance, page`. Draw at `pen + pre`, then `pen += advance`.

API: `read(&[u8]) -> Result<Font>`; `Font { size: i16, width: i16, height: i16, glyphs: Vec<Glyph> , groups }`;
`Font::glyph(cp: u32) -> Option<&Glyph>`; `Glyph { uv: [f32; 4], pre, width, advance: i16, page: i16 }`.

- [ ] Tests first: `a_code_point_finds_its_glyph_through_the_groups`, `a_code_point_between_groups_is_none`,
  `glyph_fields_read_back` (built bytes), `a_short_file_is_an_error`.
- [ ] Install test `the_dsfont_reads` (skips): size 58, 1024 x 1024, 135 groups, 1284 glyphs; `'0'` uv
  `[354, 1, 381, 59]`, pre 3, width 27, advance 27, page 0; `'1'` pre 7 width 18 advance 23; `'-'` page 6.
- [ ] fmt + clippy; PROVENANCE line (SoulsFormatsNEXT `CCM.cs`).

### Task 4: DDS decode and PNG writer

**Files:** modify `crates/dsr-cache/Cargo.toml` (`texpresso = "2"`, `png = "0.18"`); create `crates/dsr-cache/src/dds.rs`.

API: `decode(dds: &[u8]) -> Result<Image>`, `Image { width, height, rgba: Vec<u8> }` (mip 0 only; fourcc `DXT1` /
`DXT3` / `DXT5` via `texpresso::Format::{Bc1, Bc2, Bc3}`; anything else an error); `Image::crop(l, t, r, b) -> Image`
(clamped to the image; a rectangle with no pixels is an error); `Image::black_to_alpha(&mut self)`
(alpha = max(r, g, b) x original alpha / 255, colour = colour x 255 / max); `write_png(path, &Image)`.

- [ ] Tests first: `a_bc1_block_decodes_to_its_two_colours` (a hand-made 4 x 4 DXT1 DDS), `a_bc3_block_keeps_alpha`,
  `unsupported_formats_are_errors`, `crop_clamps_to_the_image`, `an_empty_crop_is_an_error`,
  `black_background_becomes_alpha` (pure red on black -> (255,0,0,255); half red -> (255,0,0,128); black -> alpha 0),
  `png_round_trips` (write to the scratch dir, read back with the `png` crate).
- [ ] `cargo test -j 4 --offline -p dsr-cache dds`; fmt + clippy.
