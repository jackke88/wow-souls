# Hogger, the Elwynn zone boss: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hogger (WoW entry 448, level 11 elite) stands at his real place in Elwynn Forest as a very hard Dark Souls-style boss, wearing the Taurus Demon's moves on the gnoll model, and a level 11 trial character exists to fight him.

**Architecture:** The extractor (`dsr-cache`) retargets the Taurus Demon (`c2250`) onto the gnoll model through a hand-made bone table and a new `Tier::Boss`; the game (`wow-souls`) adds one species (`hogger`) with a pattern table, a left-handed axe, a `Brain` tempo and a second phase (`boss.rs`), and Pierce Armor as a stacking damage-taken debuff; the importer (`wow-world`) lets a named spawn outside the valley into the world manifest; a small command writes a level 11 character slot.

**Tech Stack:** Rust (Bevy 0.18 game, `cargo` workspace at `C:\Spel\wow-souls`), benilla world engine (read-only fork), Dark Souls Remastered install (read-only), WoW 1.12.1 install (read-only), vMaNGOS DB copy (`tools/mangos-db.ps1`).

**Spec:** `docs/superpowers/specs/2026-10-13-hogger-design.md`

## Global Constraints

- Build with `-j 4` always (the machine is RAM-tight); never `cargo fmt --all` (it rewrites the benilla fork): the format gate is `cargo fmt -p wow-souls -p wow-world -p wscl -p dsr-cache -p dsr-formats -- --check`, fixed with the same line without `--check`.
- Gates after every task: that fmt line, `cargo clippy -j 4 --workspace --all-targets -- -D warnings`, and `DSR_DIR="C:/Spel/Dark Souls Remastered" WOW_DATA="C:/Spel/World of Warcraft 1.12/Data" cargo test -j 4 --workspace` (without the two variables the install tests skip silently).
- The WoW and Dark Souls installs are read-only: never write into `C:\Spel\World of Warcraft 1.12` or `C:\Spel\Dark Souls Remastered`. The vMaNGOS repack's own `mysqld` is never started on its data dir; `tools/mangos-db.ps1 start|stop|query` works on a copy.
- Nothing is committed unless the user asks (the repo has uncommitted work of other chats: `git add` only the files of a task, and only when told to commit).
- Files `main.rs`, `boot.rs`, `actor/anim.rs`, `survey.rs`, `main.rs` of `dsr-cache` have CRLF or mixed line endings: edit with the Edit tool on a re-read file, or a script that handles `\r?\n`.
- Another chat owns `weapons.rs`, `dsclip.rs`, `combat/`, `defense.rs`, `projectiles.rs`: this plan does not touch them.
- A `python -` heredoc hangs the Bash tool here: use `perl` or a script file.
- Hogger numbers (health 900, poise 40, damage_scale 1.0, tempo 1.15 in phase two, Pierce Armor +8 % damage taken per stack up to 3 for 30 s) are first guesses, tuned live in Task 9.

## Review Focus

- The `survey` tool printed the wrong creature once already (`c2860` was an ordinary enemy): every kit constant that names a chr must be checked against `NPC_name_.fmg` (Task 4 pins `c2250` = "Taurus Demon" with a test that reads the install).
- A boss whose clip has hit windows of two different judge ids (the axe `100` and the shockwave `101`) must not deal the axe's damage twice: the extractor drops windows of other judges (Task 2 test).
- A phase that is entered must not be left by healing back over the line, and must reset when the creature is reset to full health (Task 6 tests).
- Pierce Armor must clear on the player's respawn and never exceed three stacks (Task 6 tests).
- A named spawn outside the valley must not change the valley's selection (existing `select` tests stay green) and must not be thinned away by `WOWSOULS_DENSITY` (Task 7 tests).
- The trial command must never overwrite a slot that has a character (Task 8 test).

with:

```rust
    for clip in kit.clips() {
        let mut e =
            extract_clip(&source, &skel, rig, clip).with_context(|| format!("kit clip {clip}"))?;
        // A boss's blow carries windows of other judges (`a00_3000`: judge 100 is the axe, 101 the
        // shockwave on the ground): the kit names the judge it is, the rest are left out, so the
        // axe's damage is not dealt again by the shock.
        if kit.tier == monster::Tier::Boss {
            if let Some(a) = kit.attacks.iter().find(|a| a.clip == clip) {
                e.r.wow.hits.retain(|h| h.judge == a.judge);
            }
        }
```

(`e.r.wow.hits` is the `Vec` the later `ensure!`s read; for a non-boss kit nothing changes.)

use bevy::prelude::*;

use crate::species::SpeciesDef;

/// A boss's phase.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub enum Phase {
    #[default]
    One,
    Two,
}

/// The creature's phase (a component on a boss that has a second one).
#[derive(Component, Debug, Clone, Copy, Default)]
pub struct BossPhase(pub Phase);

/// The share of health at which the second phase begins.
pub const PHASE_TWO_AT: f32 = 0.5;
/// A boss back at (nearly) full health is reset: the fight starts again.
const RESET_AT: f32 = 0.99;

/// The phase for `health_fraction` (0..=1), given the current one: Two is entered at half health
/// and kept while the creature heals a little; only a reset (full health) leaves it.
pub fn phase_for(current: Phase, health_fraction: f32) -> Phase {
    if health_fraction >= RESET_AT {
        Phase::One
    } else if health_fraction <= PHASE_TWO_AT {
        Phase::Two
    } else {
        current
    }
}

/// What a phase changes.
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct Mods {
    pub tempo: f32,
    pub chase: f32,
    pub cooldown: f32,
}

impl Phase {
    pub fn mods(self, species: &SpeciesDef) -> Mods {
        match (self, species.phase_two.as_ref()) {
            (Phase::Two, Some(p)) => Mods {
                tempo: p.tempo,
                chase: p.chase,
                cooldown: p.cooldown,
            },
            _ => Mods {
                tempo: 1.0,
                chase: 1.0,
                cooldown: 1.0,
            },
        }
    }

    /// The pattern table in force.
    pub fn table(self, species: &SpeciesDef) -> &'static [crate::pattern::Row] {
        match (self, species.phase_two.as_ref()) {
            (Phase::Two, Some(p)) => p.table,
            _ => species.table,
        }
    }
}

/// The clock multiplier of a creature's swing and kit clip (1 outside a boss's second phase).
#[derive(Component, Debug, Clone, Copy)]
pub struct Tempo(pub f32);

/// How many stacks Pierce Armor holds at most, how long they last (s), and what each costs the
/// player (a share more damage taken: Hogger's spell takes armour, the game models it as damage).
const MAX_STACKS: u8 = 3;
const SHRED_SECS: f32 = 30.0;
const SHRED_PER_STACK: f32 = 0.08;

/// Pierce Armor on the player.
#[derive(Resource, Debug, Default)]
pub struct ArmorShred {
    stacks: u8,
    left: f32,
}

impl ArmorShred {
    pub fn add(&mut self) {
        self.stacks = (self.stacks + 1).min(MAX_STACKS);
        self.left = SHRED_SECS;
    }

    pub fn tick(&mut self, dt: f32) {
        if self.stacks > 0 {
            self.left -= dt;
            if self.left <= 0.0 {
                self.clear();
            }
        }
    }

    pub fn clear(&mut self) {
        *self = ArmorShred::default();
    }

    /// What the damage taken is multiplied by.
    pub fn factor(&self) -> f32 {
        1.0 + SHRED_PER_STACK * f32::from(self.stacks)
    }

    pub fn stacks(&self) -> u8 {
        self.stacks
    }
}

/// Species whose blows pierce armour.
pub fn pierces(species: &str) -> bool {
    species == "hogger"
}

/// Each boss's phase follows its health; a phase change is logged once.
pub(crate) fn phases(
    mut bosses: Query<
        (&crate::species::Species, &crate::combat::Health, &mut BossPhase, &mut Tempo),
        With<crate::species::Boss>,
    >,
) {
    for (species, hp, mut phase, mut tempo) in &mut bosses {
        let next = phase_for(phase.0, hp.cur / hp.max.max(1.0));
        if next != phase.0 {
            info!("boss: {} is in phase {next:?}", species.0.name);
            phase.0 = next;

}

use std::path::Path;

use crate::character::Character;

/// The 1.12 XP needed in all to reach `level` (the `player_xp_for_level` table, cumulative).
pub fn xp_for_level(level: u32) -> u32 {
    const STEP: [u32; 11] = [400, 900, 1_400, 2_100, 2_800, 3_600, 4_500, 5_400, 6_500, 7_600, 8_800];
    STEP.iter().take(level.saturating_sub(1) as usize).sum()
}

/// What a level 11 warrior wears: `(slot key, item)` as the items save names the slots.
pub const GEAR: &[(&str, u32)] = &[
    ("mainhand", 1219),
    ("offhand", 6560),
    ("chest", 2977),
    ("legs", 6546),
    ("feet", 6551),
    ("hands", 6547),
    ("wrists", 9785),
    ("waist", 6548),
];

/// Writes slot files into `dir`. Refuses a directory that already holds a character, and a level
/// outside 6..=12.
pub fn write(dir: &Path, level: u32, name: &str) -> Result<(), String> {
    if !(6..=12).contains(&level) {
        return Err(format!("level {level}: the trial characters are 6 to 12"));
    }
    if dir.join("character-v1.txt").exists() {
        return Err(format!("{} already holds a character", dir.display()));
    }
    std::fs::create_dir_all(dir).map_err(|e| e.to_string())?;
    let mut character = Character::new_default();
    character.name = name.to_string();
    let put = |file: &str, text: String| {
        std::fs::write(dir.join(file), text).map_err(|e| format!("{file}: {e}"))
    };
    put("character-v1.txt", character.to_text())?;
    put(
        "quests-v1.txt",
        format!("wsquests 1\nname\t{name}\nxp\t{}\nmoney\t0\n", xp_for_level(level)),
    )?;
    let mut items = String::from("wow-souls-items 1\nitem 9000001 8\nkit 1\n");
    for (slot, item) in GEAR {
        items.push_str(&format!("equip {slot} {item}\n"));
    }
    for spell in [100, 6673, 6343] {
        items.push_str(&format!("learn {spell}\n"));
    }
    put("items-v1.txt", items)?;
    put("souls-v1.txt", crate::bloodstain::to_text(2000, 0, None))
}
