# Quest return compass implementation plan

**Goal:** an Elden Ring inspired horizontal compass that tells the player which way to run to hand in completed quests.

**Architecture:** one native HUD module, existing Georgia font and worn-gold palette, a thin fading line with ticks, N/E/S/W and a center diamond. Derive camera heading from the actual view transform (including lock-on/freecam). Cache completed-quest destinations from the real quest log and manifest; use live NPC positions where available and choose the nearest site for duplicate NPC entries. Show only return-ready quests. Targets outside the front semicircle stay at the appropriate edge with a turn arrow. Group overlapping directions and show the focused NPC's name/distance. Hide with modal UI and clean up on leaving gameplay. Original overhead markers and the map remain unchanged.

**Tech stack:** existing Rust, Bevy 0.18 UI, wow-world quest rules, world spawn book. No generated art, dependencies, routing service, save-format or input changes.

Compared: rotating mini-map would duplicate the map and cover more of the world; nearest-target-only arrow would hide other completed quests; a quiet horizontal compass with grouped return targets gives useful bearings while matching the reference (chosen). Native gradients/ticks are sufficient; no bitmap generation needed.

1. Create `crates/wow-souls/src/hud/compass.rs`, register only in `hud/mod.rs`. Keep bearing, angle wrapping, projection, grouping and return-ready destination extraction pure enough to test. Cover N/E/S/W in the actual WoW-to-Bevy coordinate contract, camera seams, behind-camera arrows, vertically pointing camera, arrival, duplicate NPC sites, multiple quests for one NPC and removal after reward/abandon.
2. Build top-center anchored HUD in 720p logical units, fading gold rule, hairline ticks, serif cardinal labels, center diamond, small gold question marks and centered count badges. Use parent nodes for padding/centering. Show focused destination and rounded yards; near the NPC show ready-to-return. Keep behind-camera targets visible at edges and avoid overlap. Use current camera transforms after PlaySet::Camera; observe menu/modal gates.
3. Cache quest-derived data on completed-id changes. Per-frame work is only heading, player/live NPC positions and a bounded set of UI transforms. Add optional `WOWSOULS_COMPASS_TRACE=1` for verification, no new user interaction.
4. Build `cargo build -j4 --offline -p wow-souls`; copy an isolated preview, never kill the user's game. Run package fmt, workspace Clippy and install-enabled workspace tests with both install env variables. Record unrelated parallel animation failures separately.
5. Isolated live captures: 720p, 1080p and ultrawide; no completed quest, ready target ahead, left/right/behind, camera orbit/seam sequence, several return destinations/overlap, NPC arrival, complete-to-reward and menu/map hiding. Use real quest states and isolated saves; preserve all original NPC signs. Inspect screenshots and trace headings, then update `docs/log/2026-10-16-compass.md` and the slim handover (under 8192 bytes). No commits or publication.
