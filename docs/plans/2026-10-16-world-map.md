# Reusable parchment world map

User: add the map, bring it toward Elden Ring cheaply, reuse existing material. Continue the approved native UI direction; no commits and leave animation work alone.

**Goal:** an Elwynn area map opened with M or the system menu, showing the actual player and one optional saved marker, with pan/zoom and readable keyboard, mouse and gamepad controls.

**Architecture:** reuse WoW's hand-drawn zone tiles, WorldMapArea projection and WorldMapOverlay placement from the read-only install. Compose once in memory; apply one restrained olive/sepia grade, keeping text and geography intact. Reuse existing fonts, trim and menu pause/input ownership. No new generated assets, dependencies, extracted map files in the repo, fast travel or automatic enemy/quest-pin clutter. The loader takes an area id so the same treatment works on other zones.

Compared approaches: direct color tint is cheapest but retains the strong original palette; composing and grading the original tiles adds little code/runtime cost while retaining geographic accuracy (chosen); redrawing each map requires new art and alignment work for every area.

**Reference:** [Bandai Namco's gameplay/map overview](https://www.bandainamcoent.com/news/elden-ring-introduction-part-3-gameplay-overview), especially sparse player-placed markers and discoverable terrain. This is visual inspiration, not a claim of exact reproduction or a new exploration progression system.

**Tech stack:** existing Rust, Bevy 0.18, benilla-formats BLP/DBC readers and benilla-world projection. Existing UI material sheets.

1. Add `cartography/{mod,art,view}.rs`: pure projection/view math, strict per-character marker serialization, bounded pan/zoom, atlas composition and grading; tests cover round trips, crop boundaries, overlay tile placement, marker corruption and authentic Elwynn assets/projection.
2. Register the module in `main.rs`/`boot.rs`. Add a rebindable Map action (M); keep existing gamepad bindings and expose Map through the system menu. Map owns a system-menu page so existing pause/cursor/game-input rules apply. Generic menu row input must not consume map zoom/pan/confirm.
3. Build the map screen: clipped chart canvas, ivory/gold player and marker, understated heading/compass/crosshair, visible zoom/recenter/clear/close controls, bounded scale and consistent input hints. Keep actual installed art out of saved screenshots/assets except local gitignored evidence.
4. Build once to an independent preview executable if the normal output is locked. Capture 720p, 1080p and ultrawide, pan/zoom bounds, place/remove/reload marker, open/close input, system-menu entry and unavailable-data behavior, using isolated saves. Run scoped fmt, workspace Clippy and install-enabled tests; report unrelated animation failures separately.
5. Update the UI ledger and slim handover with implementation, evidence, asset reuse and validation. No commits or external publication.
